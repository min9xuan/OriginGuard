# M6.2 受控 Web 安全调查

## 目标

工作台现在可以把包含明确 HTTP/HTTPS URL 的钓鱼、诈骗、域名、证书或恶意风险问题路由为 `WEB_SECURITY_INVESTIGATION`。该路径与普通问答、媒体取证相互独立，输出可核验的网络观察、IOC、风险信号、执行轨迹和公开网页线索。

第一版定位为防御性初筛，不是漏洞扫描器，也不会执行攻击载荷。

## 处理流程

```text
用户问题与 URL
  -> 意图路由
  -> URL 安全策略
  -> DNS 解析与公网地址校验
  -> 固定解析地址的 TLS/主机名核验
  -> URL 与证书风险规则
  -> 可选普通网页威胁线索检索
  -> 确定性风险分与人工核验提示
```

结果持久化在工作台消息的 `grounding.webSecurityInvestigation` 中，包括：

- 目标 URL、域名、端口和解析地址；
- IOC（URL、域名、IP）；
- TLS 协议、证书主体、签发者和有效期；
- 风险信号、分值与风险等级；
- 每一个受控调查阶段及状态；
- 实时搜索提供方、来源数量和能力边界。

## SSRF 与提示注入边界

在任何主动连接之前，系统会执行以下约束：

- 仅允许 `http://` 和 `https://`；
- 禁止 URL 内嵌用户名或密码；
- 仅允许 80 和 443 端口；
- 阻断 localhost、`.local`、`.internal`、`.lan`；
- DNS 任一结果为回环、RFC1918、链路本地、CGNAT、保留、文档或组播地址时终止调查；
- TLS 连接直接使用已经验证的公网 IP，并使用原域名完成 SNI 和主机名验证，降低 DNS 重绑定风险；
- 不下载目标页面正文、不执行 JavaScript，也不把目标内容发送给 LLM。

公开搜索片段属于不可信调查线索，只展示给用户核实，不直接修改确定性风险分。

当 `TAVILY_API_KEY` 已配置时，系统会把目标域名和通用的 phishing/malware/scam 查询词发送给 Tavily。涉及保密域名时应关闭 `WEB_SEARCH_PROVIDER`，此时 DNS、TLS 与本地规则仍可运行，但不会产生公开网页线索。

## 当前评分

第一版风险分只衡量当前可见的 URL、DNS 和 TLS 风险信号：

- 明文 HTTP；
- TLS 或主机名无法验证；
- Punycode 域名；
- 直接使用 IP；
- 域名层级过深；
- 登录、验证、支付、奖励等社会工程词汇；
- 嵌套跳转参数；
- 证书临近到期。

低分不等于网站安全，高分也不自动等于恶意。结果必须结合品牌所有权、页面快照、威胁情报和人工调查确认。

## 后续扩展

需要页面级分析时，应新增隔离的浏览器工作节点，而不是让主服务直接抓取页面。工作节点至少需要：

- 独立网络命名空间和出口策略；
- 禁止访问云元数据、内网和控制平面；
- 限制响应大小、重定向次数、执行时间与下载类型；
- 页面快照、DOM、表单和二维码作为不可信证据保存；
- 内容提示注入隔离；
- 接入 MISP/OpenCTI、Google Safe Browsing 或企业威胁情报。

# M4.3 本地真实 Embedding

## 完成范围

- 使用 `BAAI/bge-small-zh-v1.5` 生成 512 维、L2 归一化的真实中文语义向量。
- 模型由 Python `model-api` 本地加载，运行时禁止联网拉取权重。
- Java `HttpEmbeddingProvider` 通过受控 HTTP 接口请求向量，不直接加载 Python 模型。
- `knowledge_chunk_embedding` 支持同一个 Chunk 保存多个 Provider 的向量，保留原 64 维确定性基线。
- 管理员可对当前租户的已发布、当前版本 Chunk 执行重新向量化。
- 模型、虚拟环境、缓存和临时文件统一位于项目 `.runtime`，该目录不提交 Git。

## 写入数据流

```text
KnowledgeDocumentService.publish() // 切分新发布的知识文档并选择当前 Embedding Provider
→ HttpEmbeddingProvider.embedAsVector() // 将单个 Chunk 发送给本地模型 API
→ POST /v1/embeddings // 使用 BGE-small-zh-v1.5 生成 512 维归一化向量
→ KnowledgeRepository.insertChunk() // 保存版本化 Chunk 原文
→ KnowledgeRepository.upsertEmbedding() // 按 Chunk + Provider 保存真实向量
```

## 检索数据流

```text
KnowledgeRetriever.search() // 使用当前 Provider 生成查询向量
→ KnowledgeRepository.search() // 只连接同租户、同 Provider、当前发布版本的向量
→ pgvector cosine + PostgreSQL FTS // 计算 70% 语义分数和 30% 关键词分数
→ RagEvaluationService // 展示 Top-K 或计算 Recall@K、MRR
```

## 重新向量化

`POST /api/v1/knowledge-documents/reindex` 只处理当前租户已发布文档的当前版本 Chunk。它不会修改 Chunk ID，因此已有 Citation 和评测用例仍然有效；它也不会删除旧 Provider 向量，从而可以继续比较确定性基线与真实模型。

## 本地运行

```powershell
docker compose up -d postgres
.\scripts\start-model-api.ps1

$env:EMBEDDING_PROVIDER='bge-small-zh-v1.5'
$env:MODEL_API_BASE_URL='http://127.0.0.1:8090'
cd services/server
.\mvnw.cmd spring-boot:run
```

确定性测试基线可显式设置 `$env:EMBEDDING_PROVIDER='deterministic'`。

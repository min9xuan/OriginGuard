# M5.3 可插拔取证模型注册与动态路由

## 目标

Agent 不再把“生成内容鉴别”绑定到一个固定实现。CLIP 先提供媒体类型，模型注册中心再按照用途、媒体种类、视觉类型和优先级选择当前可执行适配器。LLM 负责规划和汇总，不伪造模型检测事实。

## 执行链路

```text
CLIP 媒体类型 Observation
→ ForensicModelRegistry.route()
→ 选择最高优先级的可用 ForensicModelAdapter
→ 模型推理
→ 统一 forensicObservation
→ MODEL_ROUTED Trace
→ AIGC_DETECTION Observation
→ LLM 综合与人工核验
```

媒体类型分类采用 v2 细分：`ANIME_MANGA`、`DIGITAL_ILLUSTRATION` 与 `VECTOR_CARTOON` 分开路由。AniXplore 只声明支持动漫与漫画，不能再接收所有插画/卡通图片。数字绘画或矢量卡通缺少跨域专用模型时，路由会标记 `degraded=true`，保留推荐但不可用的能力列表，并降级调用通用模型。

动漫与漫画命中 AniXplore 后，Harness 还会让通用生成内容鉴别模型独立读取原图执行交叉复核。两者方向一致时提高融合置信度；方向相反时输出 `CONFLICTING_EVIDENCE` 并要求补充证据；通用复核不可用时降低置信度。扩散重建信号仍是另一条辅助链路，未校准时不参与方向性投票。

## 插件接口

新增真实模型时实现 `ForensicModelAdapter`：

1. `capability()` 声明能力代码、版本、用途、适用媒体类型、标准输出和优先级；
2. `analyze()` 调用本地模型或受控模型服务并返回原始检测结果；
3. 将实现注册为 Spring Bean；
4. 若能力代码与目录中的待接入能力一致，注册中心会自动将其切换为可用并参与优先级路由。

当前可执行能力包括通用图像生成内容鉴别、可选的动漫/漫画专用鉴别和可选的扩散重建复核。数字绘画/矢量卡通跨域鉴别、三维渲染鉴别与局部篡改定位以不可用能力留在目录中；C2PA 内容来源凭证由独立 sidecar 能力负责。

AniXplore 安装脚本固定上游源码提交，并为权重生成 SHA-256 sidecar。模型健康接口公开权重完整性状态和当前决策区间，便于区分“模型可用”“权重来源可校验”和“阈值已业务校准”这三件不同的事。

## 统一 Observation

`forensicObservation` schema v1.0.0 包含：

- capability：模型能力代码、名称、版本、用途与适用范围；
- mediaKind / mediaType；
- status / applicability；
- probabilities / verdict / confidence；
- quality / visualization；
- limitations / routing。

旧任务没有这些字段时，前端保持兼容，不展示模型路由卡片。

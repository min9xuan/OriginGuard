# M2.1 Agent Harness 最小纵向切片

## 目标

M2.1 不追求“智能判断”，而是先证明一次 Agent Task 能在 OriginGuard 的真实权限和案件上下文中完整运行，并且每一步可测试、可追踪、可持久化。

```text
调查员创建任务
→ Context Builder 装配租户、用户、案件与媒体元数据
→ Fake Planner 选择版本化 Skill
→ Policy Engine 校验权限、职责、案件状态和 Tool 白名单
→ Mock Tool 返回结构化 Observation
→ 保存 Checkpoint
→ 合成 INCONCLUSIVE 调查草稿
→ 前端展示完整 Trace
```

## 实现组件

- `AgentTask`：记录目标、状态、预算、选中的 Skill、结论、失败原因和乐观锁版本。
- `AgentStep`：按顺序记录上下文、规划、工具调用、Checkpoint 和结论等 Trace。
- `AgentObservation`：保存工具产生的结构化证据观察。
- `AgentCheckpoint`：保存可恢复状态快照；M2.1 已持久化，但断点续跑留到后续阶段。
- `AgentContextBuilder`：通过既有业务查询装配上下文，不允许 Agent 直接访问 SQL。
- `FakePlanner`：确定性选择 `inspect_media_metadata@1.0.0`，便于集成测试稳定复现。
- `SkillRegistry`：声明 Skill 版本、适用案件状态、所需权限和可调用 Tool。
- `ToolRegistry`：只暴露注册工具，不允许执行任意 Shell、SQL 或 URL。
- `AgentPolicyEngine`：约束发起者必须是案件当前调查员，且继承原用户租户与权限。
- `MockMetadataTool`：只读取系统已登记的媒体元数据。

## 状态、预算与权限

任务状态为 `PENDING / RUNNING / COMPLETED / FAILED / CANCELLED`。运行和取消使用版本号避免并发覆盖；首次切片采用同步执行。

最小预算为三步，分别用于 Skill 选择、Tool 调用与结论合成。预算由服务端控制，Planner 不能自行增加。任务只能由创建它的当前案件调查员运行或取消；具有 `agent:trace:read` 的审核员和管理员可以查看租户内 Trace，但不能借此执行调查。

## API

- `POST /api/v1/agent-tasks`：创建待运行任务。
- `GET /api/v1/agent-tasks`：列出租户范围内任务。
- `GET /api/v1/agent-tasks/{agentTaskId}`：读取任务、Trace、Observations 与 Checkpoints。
- `POST /api/v1/agent-tasks/{agentTaskId}/run`：运行待处理任务。
- `POST /api/v1/agent-tasks/{agentTaskId}/cancel`：取消待处理任务。

## 明确边界

当前 Mock Tool 只使用文件名、MIME、大小和 SHA-256 等登记字段，`fileContentInspected=false`。它不读取媒体字节、不调用真实 LLM、不使用 RAG、不运行 AIGC 检测或篡改定位模型，因此最终草稿固定为 `INCONCLUSIVE`，不能被当作真实性裁决。

## 验证

PostgreSQL/Testcontainers 集成测试覆盖：完整 Fake Planner/Skill/Mock Tool/Checkpoint/Trace 链路，审核员的 Trace 读取，权限或案件状态不符时拒绝创建，以及取消后禁止运行。M2.1 完成时后端共 17 项测试通过。

## 下一步

保持 Harness 接口不变，将 Mock Tool 逐步替换为真实但受控的媒体存储、授权预览、魔数/MIME 校验、EXIF、哈希和 C2PA 工具；之后再接入 RAG、算法工具和真实 Planner。这样每次替换都能沿用现有 Trace、Policy、Budget 和测试边界。

# M6.1 Agent 行为评测基线

## 目标

Agent Evaluation 评估的是 Harness 是否合理、安全且高效，而不是重复评估底层 AIGC 模型准确率。第一版直接读取真实任务已经持久化的 `AgentStep`、`AgentObservation`、`AgentCheckpoint` 与最终结论，避免使用 Agent 自己的自然语言回答作为唯一评分依据。

## 评测流程

```text
创建评测规则
→ 选择已结束的真实 Agent 任务
→ 读取 Trace / Observation / Checkpoint
→ 确定性规则评分
→ 关键失败门控
→ 保存维度分数、违规原因和性能计数
→ 与历史运行比较
```

评测不会修改、重新运行或删除被评任务。`PENDING` 和 `RUNNING` 状态不可评测，避免读取尚未稳定的中间状态。

## 六个评分维度

| 维度 | 满分 | 主要检查 |
|---|---:|---|
| `TOOL_SELECTION` | 20 | 必须/禁止 Skill、工具调用预算 |
| `PLANNING_REPLAN` | 20 | Plan 生成与校验、重规划预算、重复决策 |
| `GOAL_COVERAGE` | 10 | 必须/禁止 Observation |
| `EVIDENCE_FIDELITY` | 25 | 是否保存证据、是否保留人工核验、最终方向是否被 Observation 支持 |
| `RESILIENCE` | 15 | 任务终态、失败状态、Checkpoint |
| `PERFORMANCE` | 10 | 总耗时和工具调用预算 |

总分达到评测规则的 `minimumScore` 才可能通过。出现下列关键失败时，无论总分多少都不通过：

- 调用被禁止的 Skill；
- 产生被禁止的 Observation；
- 没有保存任何 Observation；
- 最终结论覆盖或背离冲突模型证据；
- 评测规则要求人工核验，但结论取消了该要求。

## 数据模型

`agent_evaluation_case` 保存可复用约束：

- 必须/禁止 Skill；
- 必须/禁止 evidence type；
- 工具调用、重规划、耗时上限；
- 最低通过分；
- 是否必须完成、是否必须人工核验。

`agent_evaluation_run` 保存一次真实任务评分：

- 六维得分与总分；
- 是否通过、是否存在关键失败；
- 违规代码与说明；
- 工具调用数、重规划数、重复重规划数、耗时、Step 和 Observation 数量；
- 实际出现的 Skill、Tool 与 evidence type。

## API

```text
GET    /api/v1/agent-evaluations/cases
POST   /api/v1/agent-evaluations/cases
DELETE /api/v1/agent-evaluations/cases/{caseId}
GET    /api/v1/agent-evaluations/runs
POST   /api/v1/agent-evaluations/runs
```

读取需要 `model:read`，创建、删除和运行评测需要 `model:manage`。

## 能力边界

- 第一版评测已经执行完成的任务，不负责自动建立调查案件或上传媒体；
- 证据忠实度以结构化 verdict 和 Observation 为准，暂不对所有自然语言句子做事实蕴含判断；
- LLM Judge 可以在后续作为辅助维度加入，但不能覆盖确定性关键失败；
- 模型准确率仍由检测模型评测模块独立负责，不能用 Agent 得分替代。

## 后续扩展

1. 提供固定场景包，一键创建普通问答、单图、多图、证据冲突和工具失败任务；
2. 加入 RabbitMQ 重复投递、Redis 故障、SSE 重连与 Checkpoint 恢复评测；
3. 增加提示注入、越权调用和恶意知识文档测试；
4. 将不依赖真实模型的固定场景接入 CI，把真实模型场景作为本地或定时评测；
5. 对同一规则的不同版本运行提供趋势图和回归阈值。

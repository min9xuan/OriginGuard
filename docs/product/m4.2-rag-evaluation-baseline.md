# M4.2 RAG 检索调试与评测基线

## 完成范围

- 新增 `EmbeddingProvider` 接口，当前 `DeterministicEmbeddingService` 作为默认实现。
- 新增独立检索调试 API/页面，可查看 Top-K Chunk、原文引用及 Vector、FTS、Hybrid 分数。
- 可将“问题 + 期望文档/Chunk”保存为版本化知识之上的评测用例。
- 评测运行计算 Recall@K 与 MRR，并持久化运行结果。
- 每次运行同时校验租户隔离、草稿排除和 Citation 完整性。

## 调试数据流

```text
KnowledgeDocumentsView.search()     // 提交测试问题和 Top-K
→ RagEvaluationController.debugSearch() // 校验权限和请求参数
→ RagEvaluationService.debugSearch()    // 注入当前租户并组织调试结果
→ KnowledgeRetriever.search()           // 使用当前 EmbeddingProvider 生成查询向量
→ KnowledgeRepository.search()          // 执行租户/发布版本过滤和混合排序
→ 页面展示 Top-K、引用原文和三路分数
```

## 评测数据流

```text
addEvaluationCase()                 // 将当前问题和选中的正确 Chunk 保存为期望答案
→ createCase()                      // 校验文档属于当前租户且已发布
→ rag_evaluation_case

runEvaluation()                     // 运行当前租户全部评测用例
→ 对每个 Query 执行相同生产检索路径
→ 计算第一个相关结果排名
→ Recall@K = Top-K 命中用例数 / 总用例数
→ MRR = 每个用例 1 / firstRelevantRank 的平均值
→ 反查文档、Chunk、租户、发布版本和引用原文
→ rag_evaluation_run / rag_evaluation_result
```

## 当前边界

当前 Hash Embedding 只提供可复现基线，不代表生产语义质量。接入真实 Embedding 后，可用同一评测集直接比较 Recall@K 和 MRR，避免凭主观感受选择模型。

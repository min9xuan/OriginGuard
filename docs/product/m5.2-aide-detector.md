# M5.2 AIDE AIGC 图片检测 Skill

## 目标

将 AIDE（AIGC Image Detector with Hybrid Features）的官方预训练检查点作为真实模型工具接入 OriginGuard，而不是让 LLM 凭视觉印象直接裁决，也不把模型分数自动转换为审核结论。

## 运行链路

```text
Agent Planner
→ detect_aigc_with_aide Skill（声明能力、权限、状态和步数）
→ model.detect_aigc_with_aide Tool（只允许调用项目 Model API）
→ 从 MinIO 读取租户授权图片字节
→ POST /v1/aigc/detect
→ AIDE 官方预处理 + 官方 GenImage 权重推理
→ AIGC_DETECTION Observation
→ Agent 阶段性结论
→ 调查员确认是否纳入正式证据
→ 独立审核员引用证据并决定
```

## API 输出

每次推理保存以下字段：

- 模型 Provider、名称、版本和权重 SHA-256；
- CPU/CUDA 设备及 float32/float16 精度；
- `syntheticProbability` 与 `authenticProbability`；
- 当前实验决策边界为 0.50：不低于 0.50 为倾向 AI 生成，低于 0.50 为倾向真实；
- 原图尺寸、处理耗时和能力限制。

0.50 与 AIDE 官方二分类评测边界保持一致，但仍只是实验阈值，不代表 AIDE 分数已在 OriginGuard
真实业务数据上完成概率校准。Agent 会把该方向与 CLIP 媒体类型、质量门控和已配置的领域专用模型
结果交给 LLM 进行结构化综合，输出供审核员参考的初步判断；人工审核仍负责案件最终裁决。

CLIP 只用于媒体类型识别和模型路由，不作为 AIGC 真伪证据。卡通、3D、截图等领域模型尚未接入时，
系统会明确记录 `NOT_CONFIGURED` 并降低初步判断置信度，不会伪造对应模型结果。

## 8GB 显存策略

AIDE 检查点包含 ConvNeXt-XXL 语义分支、两条 ResNet-50 频域分支和分类头。由于本地 Qwen3-VL 也需要显存，统一启动脚本默认 `AIDE_DEVICE=cpu` 并采用懒加载，避免两套模型同时驻留 8GB 显存导致 OOM。独立性能测试可以在启动 Model API 前设置：

```powershell
$env:AIDE_DEVICE='cuda'
$env:AIDE_PRECISION='auto'
.\scripts\start-model-api.ps1
```

`auto` 默认保持与官方检查点一致的 float32。RTX 4060 8GB 单独运行 AIDE 已完成实测；如同时运行 Qwen，仍建议让 AIDE 使用 CPU。float16 仅保留为显式实验选项，因为测试中观察到了比 float32 更明显的分数漂移。

## 证据边界

- AIDE 是学习型分类器，不是内容来源证明；
- 截图、缩放、社交平台压缩和未见生成器会造成分布偏移；
- AIDE Observation 默认只是候选证据，必须由调查员确认；
- 最终决定仍由与调查职责分离的审核员作出；
- 后续应加入本项目评测集、分生成器指标、校准曲线、C2PA 和篡改定位模型。

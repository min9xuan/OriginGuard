# M1.2 人工证据与独立审核闭环

## 目标

在 M1.1 媒体记录与案件状态机上，补齐不依赖 AI 的人工调查闭环：职责分派、人工证据、提交审核和独立审核决定。管理员负责分派但不参与审核，调查员与审核员必须职责分离。

## 业务数据流

```text
管理员分派调查员与审核员
→ 调查员针对案件关联媒体追加人工观察证据
→ 调查员提交 WAITING_REVIEW
→ 系统自动创建 PENDING 审核任务
→ 指定审核员通过或驳回
→ APPROVED 对应案件 CONFIRMED
→ REJECTED 对应案件 REJECTED，可返回调查阶段补充证据
```

## 数据模型

`V3__evidence_assignment_and_review.sql` 新增：

- `case_assignment`：追加保存每次调查员/审核员分派历史；
- `investigation_evidence`：保存关联媒体、人工观察、判断结论、置信程度和创建人；
- `review_task`：保存指定审核员、任务状态、审核意见、决定人和独立版本号；
- `case:assign`：只授予内置管理员角色，不授予审核决定权限。

人工证据在当前阶段只允许新增，不提供修改或删除接口，避免调查结论被静默覆盖。后续算法证据可沿用同一证据聚合思路扩展，但不会伪装成人工证据。

## 权限和职责分离

- `ADMIN`：读取租户案件、分派调查员与审核员；不能新增证据，不能审核通过或驳回；
- `INVESTIGATOR`：只能修改当前分派给自己的案件并追加证据；必须至少有一条证据才能提交审核；
- `REVIEWER`：只能决定分派给自己的 `PENDING` 任务；驳回必须填写理由；
- 审核员不得等于案件创建人或调查员；所有用户与业务数据必须属于当前租户；
- 案件使用 `version`，审核任务也使用独立 `version`，过期写入返回结构化 `409`。

## API

```text
GET  /api/v1/cases/assignees
POST /api/v1/cases/{caseId}/assignment
GET  /api/v1/cases/{caseId}/workflow
POST /api/v1/cases/{caseId}/evidence
POST /api/v1/cases/{caseId}/reviews/{taskId}/decision
```

完整请求和响应定义见 `packages/api-contract/openapi.yaml`。

## 提交审核前置条件

案件从 `INVESTIGATING` 进入 `WAITING_REVIEW` 时必须同时满足：

1. 当前用户是分派的调查员；
2. 案件至少包含一条人工证据；
3. 已分派当前租户内启用的审核员；
4. 审核员与创建人、调查员不同；
5. 案件版本仍与客户端提交版本一致。

满足条件后，状态更新与审核任务创建位于同一数据库事务中。

## 审计动作

M1.2 新增：

```text
CASE_ASSIGNMENT_CHANGED
EVIDENCE_ADDED
REVIEW_TASK_CREATED
REVIEW_APPROVED
REVIEW_REJECTED
```

审核决定还会追加 `CASE_STATUS_CHANGED`，从而同时保留业务动作和状态变化。

## 自动化验证

后端 Testcontainers 集成测试覆盖完整通过链路，以及：

- 无证据不能提交审核；
- 管理员能够分派但不能作出审核决定；
- 审核任务只分配给指定审核员；
- 驳回意见必填；
- 审核通过后案件进入 `CONFIRMED`；
- 分派、证据、审核任务和决定均出现在案件审计时间线。

前端执行 Vue/TypeScript 类型检查、Vitest 和 Vite 生产构建。

## 后续边界

M1.2 尚不包含报告草稿、报告终签、案件归档、原始文件存储、算法证据、RAG 或 Agent。下一业务功能应优先完成确认案件的报告与归档，再进入真实媒体取证能力。

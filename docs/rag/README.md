# RAG 与生成增强

OriginGuard 通过统一的 `RetrievalOrchestrator` 调度检索。RAG 不再只是“从管理员上传文档中找几段文字”，而是按问题组合四类上下文：

1. 本地大模型已有知识；
2. 当前会话及最近上传媒体的上下文；
3. 管理员发布后的受控知识库；
4. 按需实时网络检索。

普通常识问题直接进入生成回答。涉及某张图片的真实性、生成来源或媒体取证时，系统才创建 Agent 任务；用户原问题会和固定的安全取证目标合并，知识检索用于规划与解释，实际真伪方向仍只来自已执行的媒体工具和模型观察。

系统使用两个检索配置：

- `GENERAL_ANSWER`：普通问答按需融合模型知识、会话上下文、已发布知识库与通用网页。
- `PROFESSIONAL_FORENSICS`：专业 AIGC 检测只调用学术检索，并对来源质量排序后再提供给 Agent。

## 本地知识库

- 用户数据边界、权限与发布状态在检索前过滤；草稿不会进入用户回答或 Agent 规划。
- 中文 Embedding、pgvector 与 PostgreSQL 全文检索共同参与混合排序。
- 每次命中保留文档、版本、Chunk、排名及语义/关键词分数，便于追溯。
- 管理员上传内容适合沉淀稳定资料，例如模型论文摘要、适用域、阈值校准记录、已知限制和内部操作规范。

## 实时网络检索

- `WEB_SEARCH_PROVIDER=auto` 时，有 Tavily 密钥则使用 Tavily；否则使用 OpenAlex 获取实时学术元数据与摘要。
- `WEB_SEARCH_PROVIDER=tavily` 可显式启用通用网页搜索，需要配置 `TAVILY_API_KEY`。
- `WEB_SEARCH_PROVIDER=disabled` 可完全关闭实时检索。
- 专业检测无论普通网页配置如何，均通过 OpenAlex 获取可核验学术候选，并依次优先：维护的计算机视觉/AI 顶级来源、IEEE 期刊、其他学术期刊、其余学术索引来源。
- IEEE 或其他期刊只有在有明确依据时才标注质量层级；系统不会虚构中科院/JCR 分区或 CCF 等级。
- 网络来源在界面中单独标记，不会被自动写入已发布知识库。

## 生成与证据边界

模型会用上述上下文组织更完整、可读的回答，并额外生成“检索如何影响本次回答/判断”的摘要。该摘要与引用一起展示，区分实际影响、仅作背景和没有影响的来源。

检索文本不能覆盖真实检测结果。Agent 结论中的概率、判断、正反信号和限制均取自本次实际执行记录；RAG 与网络材料只解释方案、方法、适用范围和局限，不直接构成媒体真伪证据。

这使知识库可以逐步积累，而不要求项目一开始就拥有大规模私有数据；同时仍保留已发布知识的可信边界和完整引用。

# ADR-006：分离系统管理与案件审核职责

- 状态：Accepted
- 日期：2026-08-03
- 影响版本：项目计划书 v2.1、角色与权限规划 v1.1

## 背景

OriginGuard 最初的权限矩阵允许管理员审核案件并签署最终报告。管理员同时掌握用户、角色、知识、模型、Agent 工具和系统策略配置；如果再默认拥有人工审核与终签权限，单一角色就可以配置调查条件、查看全部案件并形成最终结论，削弱 Human-in-the-loop 的独立性和审计可信度。

## 决策

v1.0 只保留三个业务角色：

- `INVESTIGATOR`：发起并跟踪调查，补充证据，提交审核；
- `REVIEWER`：独立复核证据，驳回或确认案件，签署最终报告；
- `ADMIN`：管理用户、角色、知识、模型、工具、Prompt、安全策略和系统审计，并在租户范围内查看业务数据。

管理员的内置权限不包含：

```text
review:approve
review:reject
report:edit
report:finalize
```

全局查看权限不能推导出审核或终签权限。未来如确有紧急处置需求，必须使用显式、限时、可审计的授权流程，而不是扩大管理员默认权限。

## 资源级约束

- 调查员不能审核或终签自己创建、主要负责的案件；
- 审核员不能审核自己创建或主要负责调查的案件；
- Agent 继承发起者权限，不能审核案件或签署最终报告；
- 所有角色仍受租户隔离约束；
- 已签署报告和关键证据通过版本或撤销标记修正，不直接覆盖。

## 影响

- 权限种子必须确定性移除管理员遗留的审核和终签权限；
- 后端审核与报告接口必须同时检查权限、租户、案件负责人和案件状态；
- 前端不向管理员展示审核、驳回、报告编辑和终签入口；
- 自动化测试必须覆盖管理员直接调用相关接口返回 403；
- 项目计划书与角色规划必须以此 ADR 为最终解释依据。

## 结果

该决策减少管理员账号被滥用后的业务影响范围，使“系统配置者”和“最终人工裁决者”保持独立，符合 OriginGuard 可追踪、可审计、人工最终确认的产品初衷。
